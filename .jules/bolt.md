## 2025-02-18 - [Lazy Initializing Media Elements in Leaf and Interactive Components]
**Learning:** Pre-allocating multiple HTML5 `new Audio(...)` instances inside component state arrays or local variables causes severe mounting overhead (CPU spikes and high memory usage). Furthermore, including state-based media control flags (`isPlaying`) in callback dependencies can cause cascading re-creations (`playSound` -> `askQuestion` -> `useEffect` trigger), leading to duplicate execution and rendering bugs. By migrating to static structures of string paths and using a single, lazily-initialized `Audio` instance via a React `useRef`, we completely bypass initial mounting overhead and eliminate the state dependency chain.
**Action:** Always prefer lazy-loading/on-demand instantiations of heavy DOM or system APIs (like HTML5 Audio or Canvas context) using refs rather than pre-allocating multiple instances in state or array definitions.
